# 路线图：收口计划（2026-10-14）

**这份路线图的目的只有一个：给“这个项目做到哪一步就算彻底做完”定一条线，并把到那条线的所有事情拆开。**
此前的做法是在某一块上不断往上加东西（动态角色、best-of-N、经验库、断言裁判、语言包、V2……），项目越来越大，而面试官能看到的东西没有变多。从现在起：**终点先定，范围冻结，每一项有验收和费用上限，做完一项勾一项，勾完就停。**
旧路线（2026-10-06/07 版，含主流做法的出处与取舍）已归档：[archive/ROADMAP_2026-10-07.md](archive/ROADMAP_2026-10-07.md)。

## 2. 终点：做完的定义（全部打勾就停）

- [ ] **D1 看得见**：输入需求后，用户能实时看到模型在写哪个文件、代码逐字出现、写完后与上一版本的 diff、当前在做哪一步（一句话）。
- [ ] **D2 插得上手**：任务运行中可以追加提示（记入账本，下一个节点生效）、暂停/继续/停止；需求变更（改规格）只做设计，不实现。
- [ ] **D3 能回放**：点任意一次模型调用，看到它当时收到了什么（各部分占多少 token、哪些被省略及原因）和它的输出。
- [ ] **D4 一个可量化的独特设计**：**缓存友好的上下文排布**（稳定内容在前、变化内容在后），报告里显示缓存命中 token 与费用变化，同一样本前后各测一次。
- [ ] **D5 没坏**：改完后，默认流程在 Go 和 Python 各一个小任务上真实通过一次；V2 在 Go 下真实通过一次。
- [ ] **D6 能讲清**：README 顶部有 2–3 分钟演示动图与 90 秒讲解；PROJECT_OVERVIEW 与简历按最终事实更新；文档只留三份主文档 + guides，其余归档。
- [ ] **D7 冻结**：写下冻结规则（§6）并遵守。

**不在终点里（明确不做）**：需求版本化（D2 的第 3 级）、新语言包、新的评测任务/大样本评测、经验库、新的运行方式或开关、本地模型当工人、通用 Agent 平台化、内嵌真正的 VS Code。

## 5. 与主流做法的对照（这几项为什么这样做）

| 项 | 主流怎么做 | 我们的取舍 |
|---|---|---|
| 工作台形态 | OpenHands 等的界面是“对话 + 文件变更 + 终端”分面板；Cursor/Claude Code 的核心是“代码逐步出现 + 可打断” | 沿用“文件树 + 编辑器 + 底部面板”的熟悉布局，**保留自己独有的流程带**；不内嵌 VS Code（code-server 太重、与账本/沙箱对不上） |
| 人在回路 | LangGraph 用 `interrupt()` 暂停并持久化等待输入；恢复时**会从头重跑被中断的节点** | 我们只在**节点边界**读取输入（不在调用中途打断）：不会重复付费调用，也不需要重跑；输入先写账本，崩溃后不丢 |
| 提示词缓存 | 云厂商的上下文缓存都按**前缀**匹配（稳定内容放前面）；DeepSeek 在用量里给出 `prompt_cache_hit_tokens / miss` | G4.1 的排布 + 命中计量；只量化真实命中，不预设数字 |
| 可观测与回放 | Langfuse/LangSmith 以“trace → span”展示每次调用的输入输出；OpenHands 把每个动作记成结构化事件可回放 | 账本本来就是事件溯源，G2.3 只是读模型；不引入外部服务 |

> 以上外部做法来自检索到的公开文档与通用知识，细节对外引用前请核对原文：[DeepSeek 上下文缓存](https://api-docs.deepseek.com/guides/kv_cache)、[LangGraph interrupt](https://docs.langchain.com/oss/javascript/langgraph/human-in-the-loop)、[OpenHands 功能说明](https://docs.all-hands.dev/usage/key-features)。

## 6. 冻结规则（D7）

D1–D6 全部打勾之后：
1. **只修 bug、只改文档**。
2. 新功能必须同时满足：写明一条**面试价值或用户痛点**；**替换或删除**某个现有东西（净代码不增加）；一天内能做完。三条缺一不可。
3. 不再为“某个机制效果不明”继续做评测——要么有数据支持就留，要么写“实验性”就放着。
4. 简历里只写**真实测到**的数字；没测到的写设计与取舍。
