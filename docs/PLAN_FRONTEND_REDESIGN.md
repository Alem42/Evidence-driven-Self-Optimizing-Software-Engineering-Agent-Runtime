# 工作台重构方案

2026-10-03。用户已授权实施，不新增后端状态体系。

问题：同页堆叠审核、源码、结果、日志；重复的模型入口；禁用的大输入框占空间；长流程图不方便找当前操作。

新布局：左侧项目历史；中央标签页；右侧执行状态与需求摘要。新建时只显示需求表单，进入项目后表单退场。已有项目底部用短状态栏说明是否执行/等待；未来持续对话放在此处，不提前做无效聊天框。

| 区域 | 内容 |
|---|---|
| 当前任务 | 当前方案确认、代码审核、澄清、修复或运行程序；只显示适用操作 |
| 代码 | 文件导航与只读快照；草稿可在当前任务审核编辑 |
| 验证 | 真实工具结果，规划阶段明确尚未运行检查 |
| 日志与版本 | 来源链日志、复制、历史版本、实际角色调用 |
| 状态侧栏 | 当前动作、角色时间线、完整需求；小屏展开查看 |

默认：规划/草稿进入当前任务，成功验证进入代码，失败验证进入当前任务。手动切标签不被轮询强制跳回。恢复提示只来自真实中断任务，不把持久 running 当成活动线程。没有 token 流式预览，也不伪造聊天。

实现保持 React/Vite，无新 UI 框架。拆出纯展示状态策略并测试：成功/失败/澄清/规划/中断；已有真实随机数项目用于接口和输出复验，不为纯布局重复付费生成代码。构建和接口检查不能冒充真实浏览器视觉验收。
