# 模型路由与工作台愿景

2026-10-02。此文是后续实施方案，不表示这些能力已经实现。

## 本轮先完成

执行架构减法，保留一个项目流程、Coordinator、RoleRuntime、工具 Runtime 和 Gate。工作台采用历史侧栏、紧凑阶段导航、中央代码、底部需求输入；运行期间禁止提交新的需求。使用固定 API 验收明确种子的随机数 CLI。实际模型输出目前是完整 JSON 响应，不伪造流式代码。

## 后续模型路由

不新增 Agent 图或状态机。Settings 保存配置，纯策略函数选模型，Coordinator 决定有界升级，RoleRuntime 记录实际调用。能力等级由用户指定，不代表客观评测结论。本机已检测 RTX 5070 Ti、16303 MiB；未发现 PATH 中的 Ollama，不自动下载模型。安装本地推理服务及模型需单独验证显存、延迟、JSON 契约和许可证。

| 阶段 | 改动 | 验收 |
|---|---|---|
| R0 配置 | profiles 增加 local/cloud、enabled、level、priority、roles、context_limit、timeout、可选输入输出单价；旧配置默认固定模式 | 旧配置不丢失；排序、角色和上下文筛选；本地无密钥调用 |
| R1 固定快照 | 任务开始保存路由配置内容与版本 artifact；恢复使用原快照；每次换模型创建明确的新修订 | 改配置不改变已开始任务；provider/input 一致性检查不绕过 |
| R2 本地优先 | 首选满足角色和上下文的本地模型；真实失败先同等级自修一次，再升更高等级；保留规格、测试计划与冻结测试 | 本地成功、自修成功、升级成功、最高等级失败；总修复最多四轮 |
| R3 总预算 | 同一任务累计调用、云端 token、可选费用、墙钟时间；每次请求前预留上限，响应后结算 | 耗尽停止；未知用量标未知，不能当零；缺价格时不声称满足费用上限 |
| R4 辅助路由 | 开始时调用一次指定模型，返回 Planner/Tester/Developer profile ID 与理由；代码验证 | 禁用或不匹配建议拒绝；明确失败回退 R2；路由费用入账 |
| R5 比较 | 同一组任务比较固定 API、本地优先、辅助路由 | 报告云 token/费用、通过率、耗时、升级次数及缺失数据 |

每个等级最多一次自修，所有等级合计最多四轮。模型调用上限与 token/费用/时间上限是全任务约束，不因创建新 Run 重置。升级只继续失败阶段，传入批准规格、相关源码、真实诊断、修复摘要。升级账本包括原模型、新模型、等级、原因、关联失败证据及新调用身份；旧调用不可覆盖。

失败处理：代码或测试缺陷沿现有分类修复；JSON/契约错误计入有界失败；配置、鉴权、工具环境错误停止并提示，不归因能力。已发出但结果不确定的请求不得自动重放或换模型；同一断言反复失败沿用停止规则，不能删除或削弱断言。本地长调用允许可配置超时，取消与不确定结果仍须保留。模式 B 无效建议或明确失败回退模式 A，不确定结果不能回退掩盖。路由只能推荐已有且启用、满足角色与上下文限制的模型，不能改需求、工具权限或预算。

必要回归：中断前后路由一致；未知请求不重放；预算不重置；升级不能改冻结测试；所有上述成功/失败分支。界面显示实际模型、等级、尝试、升级原因、累计用量，配置按等级/优先级排序。

## IDE 工作台方向

持续保留底部对话框，未来允许追加需求、提问回答和修改。输入会形成需求新版本并明确影响范围，不能在验证期间直接改快照。中央文件区持续显示代码，左侧保存项目历史，顶部仅显示阶段和当前动作；工具输出、日志、历史版本和审查细节折叠。

真正流式输出需先扩展 provider 与 HTTP 事件传输：文本增量仅作预览，完整响应经 JSON/文件校验后才能成为草稿。断线不得触发重复模型调用；不得把部分 JSON 作为可批准代码。先做事件进度，再做只读 token 预览，最后做版本化持续需求输入。模型路由先于任意动态图和并发。
