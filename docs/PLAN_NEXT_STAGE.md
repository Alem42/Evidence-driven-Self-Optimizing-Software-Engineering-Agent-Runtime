# 下一阶段：真实整项目验收与程序启动

2026-09-28。C 最小链路已实现：批准架构 → Developer 文件集合 → 人审 → 项目快照 → 独立验证。下一轮不重做规划/生成接口。

| 优先级 | 增量 | 验收 |
|---|---|---|
| 最高 | 小型真实 LLM 项目验收 | 使用现有会话配置生成 CSV/文本处理 CLI；记录实际 token、文件清单、业务测试与失败原因，不自动重试付费请求 |
| 高 | 反馈后重生成 | 引用失败检查和原提案，创建新草稿；用户可明确补充需求；旧批准与旧证据保留 |
| 高 | 固定入口 go run | Go runner 新操作，结构化 argv，不接受 shell；前端参数、stdout/stderr、退出码、超时与停止；测试与程序输出分开 |
| 中 | 使用便利 | 项目文件浏览和 ZIP 导出；提升错误提示、长输出和实际浏览器视觉/点击验收 |
| 后置 | 扩展 | 分文件生成、HTTP 模板、第三方依赖、多轮修复与 Reviewer 语义审查 |

本轮已通过 90 Python / 4 frontend 测试与真实 Go 固定提案执行；没有真实上游生成质量验证。优先先验证小型项目，不直接扩大文件上限。

继续保持角色决策、检查动作、Runtime 校验、独立 Gate 的职责边界。不要让 Reviewer 的评价覆盖真实失败的工具结果。
