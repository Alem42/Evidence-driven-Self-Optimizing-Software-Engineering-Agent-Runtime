最新优先级：用户要求尽快看到纯本地效果，优先 GLM-4.7-Flash 和 Ollama 控制页。暂停推进云端/自动升级/辅助路由，先解决本地角色契约和生成验证。已实现的固定快照、审批、冻结测试和 Gate 保留；不自动回退 API。下表为本地闭环可用后的路线，不代表本轮立即实现全部。

## 分阶段交付

| 顺序 | 阶段 | 交付与验收 | 状态 |
|---|---|---|---|
| 1 | R0 配置与固定调用 | 本地/云端统一管理、无密钥 Ollama、旧 API 兼容、真实本地工具闭环 | 已实现；完整本地项目生成待验收 |
| 2 | R1 任务配置快照 | 开始时固定配置；改设置后恢复仍使用原配置；上下文准入检查 | 固定配置恢复已实现；digest/上下文准入待做 |
| 3 | R3 全任务预算 | 跨规划、生成和修复累计调用、时间、云 token 和可选费用 | 未实现，必须先于自动升级 |
| 4 | R2 本地优先与升级 | 当前模型自修一次，仍失败升更高等级；只续失败阶段 | 未实现 |
| 5 | R4 一次辅助路由 | 路由模型推荐三个角色的配置 ID；校验后执行 | 未实现 |
| 6 | R5 同任务对照 | 固定 API、本地优先、辅助路由的真实结果报告 | 未实现 |

每阶段独立验证、提交、更新 CURRENT。遇到真实模型失败，保存证据，不把失败隐藏为成功；不为了跑通测试放松 Gate。

## R0：当前最小可用能力

Settings profiles 增加 model_type、protocol、enabled、level、priority、roles、context_limit、timeout_seconds，以及可选输入/输出单价。默认本地 L1、云端 L2，数字越大表示用户认为能力越强；同等级 priority 越小越先。允许用户改等级，不声称自动测得能力。

Ollama 原生地址使用 http://127.0.0.1:11434，不含 /v1；兼容协议通常使用 /v1。原生调用走 /api/chat、完整 JSON、非流式响应，保存服务返回的实际 token 用量。本地允许无密钥，云端继续要求密钥；本地第一版只接受回环地址。旧云端调用身份保持不变，不借适配绕过历史一致性检查。

当前选择的是固定模型，不因配置了等级就自动升级。角色限制已在调用边界检查；context_limit 对 Ollama 设置 num_ctx，对云端目前仅保存配置，尚无请求前 token 准入保证。单价仅保存，尚未计算任务费用。

新原生本地草稿 files-v1 逐文件落盘，单文件与修复 schema 限定批准路径，Domain 独立验证；旧草稿/云端 bulk 保留兼容。GLM多文件仍有质量/输出上限问题。Qwen小CLI经明确测试修订后Go/Gate与五项独立探针通过，见进展005；不是自动升级或通用成功率证明。先前云端随机数记录不作为本轮本地验收。

## R1：冻结选择，保证恢复一致

已实现固定模式：Settings.provider 绑定无密钥配置快照；自动任务创建时保存完整快照，首次角色请求原子保存 artifact 引用。恢复优先原快照，改模型/等级/输出参数不隐式改变旧任务；删除、禁用或改目的地址明确拒绝。凭据仍从原 profile/原地址读取，不存进快照。旧无快照任务沿原路径兼容。当前仅固定模式单模型；本地 digest、上下文准入和未来候选集合仍待完成。

任务起点保存版本化路由 artifact：模式、候选 profiles、协议/地址/模型、等级/优先级、角色、上下文/输出限制、超时和价格。不存密钥；密钥沿现有 Settings 获取并校验配置关联。新 Run 和修订都引用同一任务快照。用户修改或删除配置不能导致旧任务隐式换模型；不可恢复时明确停止。

本地模型 tag 可被覆盖，应记录服务返回的 digest；恢复发现变化时要求明确处理。云端同名模型的服务端权重不可由 MASA 保证冻结，报告此限制。快照与调用输入/provider 一致性检查并存，不放宽原有校验。

增加调用前上下文准入：为输出和系统提示预留空间，超过限制先按现有 ContextBuilder 裁剪可裁剪证据，不能丢批准规格或冻结测试约束；仍不满足则拒绝该候选。估算需注明，不能把 num_ctx 配置等同于输入不会被服务截断。

验收：设置变化、删除 profile、本地 digest 变化、服务重启、已收响应复用、未知请求不重放、上下文超限、旧固定 API 恢复。

## R3：预算必须覆盖整个任务

沿现有任务/调用账本累计，不为子 Run 新建可重置额度。预算含模型调用次数、任务时间、云输入/输出 token，可选人民币费用；路由调用也算。每次请求前预留输出上限，收到真实用量后结算，恢复重建同一余额，不能重复结算。

缺用量标未知，不能当零；缺单价不宣称费用上限有保证。费用预算要求有可信价格，否则拒绝该计费候选或明确要求用户调整预算模式。已发出结果未知的请求保留预留与保护状态，不能自动重放。优先使用保守上限，说明上下文估算的误差边界。

验收：所有阶段合计耗尽、修订不重置、路由费用、缺价格/用量、中断前后余额一致、未知请求仍占预留。

## R2：确定性选择与有界升级

简单策略函数只从快照中筛选启用、角色允许、上下文满足的候选。模式 A 初次优先本地，再按 level、priority 和稳定 ID 排序；明确记录无本地候选时使用云端的原因。固定模式仍不自动换模型。

Coordinator 在真实失败后决定：每个等级最多一次自修，仍失败选择严格更高等级的可用模型；所有模型合计最多四轮修复，并受 R3 预算限制。没有更高等级或预算不足则停止并给出证据。升级只续失败阶段，不重新生成已批准规格与测试计划。

每次换模型创建新修订/调用身份，记录旧模型、新模型、等级、升级原因、失败证据与预算；RoleRuntime 保留每次实际调用，不能覆盖旧记录。传递批准规格、相关源码、真实诊断和简短修复历史。实现修复冻结测试；测试准备缺陷仍走独立测试修订。

| 失败 | 决策 |
|---|---|
| 已确认代码或测试缺陷 | 沿现有分类修实现或修测试，再决定升级 |
| 已收到坏 JSON/契约响应 | 计入有界失败，可升级；保留响应证据 |
| 配置、鉴权、工具环境问题 | 单独停止/处理，不归因为模型弱 |
| 请求发出、结果未知 | 不重放、不通过换模型掩盖 |
| 同一断言反复失败 | 保留现有停止规则；不能删除或削弱断言 |

验收：本地直接成功、本地自修成功、升级 API 成功、最高等级失败、预算耗尽、未知请求、中断恢复、不能修改冻结测试。

## R4 / R5：最后才加辅助决策与比较

模式 B 开始时只调用一次用户指定路由模型，读取需求、快照和简短任务特征，结构化推荐 Planner/Tester/Developer 的 profile ID 和理由。代码验证角色/上下文/启用状态，不能改需求、工具权限、预算或增加节点。无效建议或明确失败回退 A；请求未知不得回退掩盖。执行失败继续 A 的升级规则，不重复询问路由模型。

对照任务先用明确种子的随机数 CLI，再用文本统计、整数求和、CSV 汇总等标准库小任务。保存最终检查结果、云 token/费用、总耗时、升级次数、缺失数据。统一测试输入和预算，不用不同任务宣称节省比例。配置页面按等级/优先级排序；执行页面仅显示真实已发生的当前模型、尝试、升级与用量，不展示虚构进度。

## 代码归属

| 位置 | 职责 |
|---|---|
| infrastructure/settings.py、llm.py | 配置与提供商传输，不决定修复/升级 |
| application 内的小型路由策略模块 | 纯候选筛选，不执行模型/工具、不持久化新状态机 |
| Coordinator | 使用策略、预算和失败证据决定下一步 |
| RoleRuntime / Store / artifacts | 持久调用身份、快照、用量和恢复证据 |
| ContextBuilder | 组装与裁剪角色输入，不修改批准规格 |
| 工具 Runtime / Gate | 保留白名单、快照和真实检查，模型路由不能越权 |
| React settings / workbench | 模型配置和实际状态展示 |

不按模型种类复制 Planner/Developer 类；复用同一角色协议。先通过小模块接入已有流程，避免把 Coordinator 继续堆成一个大文件。
