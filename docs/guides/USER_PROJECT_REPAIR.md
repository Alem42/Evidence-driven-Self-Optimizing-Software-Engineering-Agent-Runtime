# 在前端修复生成的项目

在运行列表选择一个验证失败的生成项目，打开“运行结果”。

1. 查看自动展开的失败输出，确认是编译、测试或格式问题。
2. 在“验证失败 · 下一步修复”中选择 API，可以补充说明。
3. 点击“根据失败证据生成修复”，一次模型调用，不自动循环。
4. 查看修复草稿的改动文件；展开修复前内容作对照。测试文件和 go.mod 为只读。
5. 批准整套代码后，Runtime 创建关联的新项目版本并重新验证。

旧失败记录不会被覆盖。测试仍失败可继续检查原因，再显式请求新一轮修复；没有未知结果时的自动重试。模型不保证能修好，Gate 只看真实结果。

如果需要改变测试或需求，应重新规划或明确调整规格；该修复流程不会允许修改测试掩盖错误。

已验证示例：失败 run 4fe9244c60044d9ab531707aa17151a3 → 修复草稿 c8d8d566ad3a4b9eab9f85a3ab3293ac → 成功执行 1d354cbafd8e4242b08b5306bf46cd5b。
