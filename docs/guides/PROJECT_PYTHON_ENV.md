# 项目内的 Python 环境与新任务页的开跑前估计

## 1. 为什么有一套项目自己的 Python

Go 的工具链放在 `.tools/go`；Python 同理：**生成的项目跑在 `.tools/pyenv`**（一个虚拟环境）。好处：
- 生成项目需要的第三方包只会装进这里，**不会弄脏 masa 自己的 `.venv`，更不会碰系统环境**；删掉目录 = 回到干净状态；
- 解释器与包是可复现的一部分（评测、回放要有固定环境）。

创建：`scripts/setup-env.ps1` 会顺手建；也可以在 **设置 → 语言 → Python → 创建项目环境**（约 7 秒）。没创建时退回运行 masa 的 Python（行为和以前一样）。

## 2. 设置（设置 → 语言 → Python）

| 项 | 含义 |
|---|---|
| 使用的解释器 | 默认“项目环境”。想用本机别的环境：**从列表里选**（自动发现 py 启动器与 PATH 里的 Python），或点 **浏览…** 在系统的“打开文件”对话框里选 `python.exe`。**不用手写路径** |
| 第三方包 | **每次都询问我（默认）** / **完全访问：允许自动安装（仅项目环境）** / **禁止：只用标准库** |
| 项目环境大小上限（MB） | 默认 500；装完超过上限，**这次新装的包会被撤销**并报告 |
| 手动安装第三方包 | 在设置页输入包名点“安装”，等于你批准了 |
| 重置为干净环境 | 删除并重建 |
| 补装 pytest | 测试框架选了 pytest、而项目环境里还没有它时出现 |

## 3. 安装的规则（为什么能放心点“允许”）

- 只接受 **PyPI 的包名（可带 `==版本`）**；URL、本地路径、命令行选项、extras 一律在运行任何命令之前被拒绝。
- 只装**预编译 wheel**（`--only-binary=:all:`）：源码包的安装会执行包作者的 `setup.py`，那是任意代码执行。
- 装进的地方永远是 `.tools/pyenv`；子进程的环境变量里 `PYTHONPATH`、`PYTHONHOME`、`VIRTUAL_ENV` 被去掉，masa 自己的包不会泄漏进项目环境。
- 超过大小上限就撤销。**完全访问不是“能碰系统”**，只是“项目环境里不再逐次询问”。

## 4. 需求里点名了第三方包时（新任务页）

例如“用 numpy 求平均值”：预检会把它从“不可能”降成“有风险”，并在输入框下面出现一张卡片：
- 策略“询问”：**允许安装 numpy**（装进项目环境）或 **改成只用标准库**（在需求末尾追加一句）；决定之前**开始按钮是灰的**；
- 策略“完全访问”：开始任务时自动装；
- 策略“禁止”：只能用标准库（预检仍当作不可能）。
装好后，静态检查放行这些包，Planner/Developer/工人的提示里会列出“可以导入的第三方包”。

## 5. 开跑前估计（新任务页）

你一边写需求，页面一边：
1. **立刻**给一个“按规则”的估计（按目标长度的经验公式 + 可行性规则）；
2. **约 1.3 秒后**让**本地模型**快速看一眼，页面显示“本地模型正在推测任务规模…”，随后给出：难度 L1–L10、约几个文件、**系统能不能处理**（可以 / 有风险 / 处理不了）和一句原因；
3. **云端 API token 三档**：经济（0.6×）/ 标准（1×）/ 充足（2.5×），基线沿用评测的单任务上限公式 `40 000 + 15 000 × 等级`；每档旁边是**价格区间**（各云端模型“token × 单价”的最低到最高，输入输出按 85:15 折算，不含缓存折扣；没设价格的模型会注明）。选中的档位就是任务的 **API token 上限**；你在高级设置里手填过，就不再被覆盖。

只算云端 API（本地模型不计费）。**这是建议，不是承诺**：本次 LCS 运行估计 100k、实际 96k，只有这一个对照。本地模型不可用、或有任务正在跑时，退回规则估计并在页面注明。

## 6. 推荐任务

首页的三个推荐来自内置题库（清晰 / **模糊需求** / 数据处理 / 小游戏与模拟 / 多包协作）加评测题库里的低等级题，**总是混进一个模糊需求**，“换一批”会避开上一批。模糊需求是故意的：看系统会先问你，还是选常见约定并写进验收。（对“不好写自动测试的模糊任务，让程序自己判断怎么验证、最后给你一个验证方法”只写进了路线图，**没有实现**。）
