# 使用工作台

前后端分离：先启动后端 API，再启动前端（先关闭旧服务）。

```powershell
# 终端 1：后端 API（默认 8765，只监听本机）
.\.venv\Scripts\python.exe -m masa serve --port 8765

# 终端 2：前端（首次需要 npm install）
cd frontend
npm install
npm run dev        # http://127.0.0.1:5173
```

或一键：`.\scripts\dev.ps1`。后端地址不同时，在 `frontend/.env` 设置 `VITE_API_BASE`；前端换了端口，用 `masa serve --origin http://127.0.0.1:端口` 加入白名单。生产式预览：`npm run build && npm run preview`（4173，已在默认白名单）。

## 界面

1. **左侧**：任务历史（进行中 / 待我处理 / 最近）、搜索、「＋新任务」；底部是设置、本地模型、主题。
2. **新任务**：输入需求，选模型与执行方式（逐步确认 / 自动执行），⌘/Ctrl+Enter 开始。
3. **任务页**：顶栏显示真实状态、模型、计时、文件进度与最近 tok/s；其下是执行图（可展开为画布与版本分支）；点击节点在右侧详情查看调用、耗时与原始响应。
4. **对话·决策**：回答 Planner 的澄清问题、编辑并确认方案、审核代码、失败后选择「修复实现 / 修订测试」、通过后运行程序。
5. **代码**：文件树 + 编辑器；审核阶段可直接编辑并「批准并验证」；出错行标红；修复版本可对比修复前。
6. **验证 / 日志与版本**：真实工具结果（失败线索可点击跳转到源码行）、来源链日志、版本分支。
7. **设置**：模型配置、本地运行时（Ollama、硬件）、路由与预算（预留）、Harness、诊断。

「跟随执行」开启时页面跟着执行中的版本走；你主动点历史或节点后它自动关闭，后台事件只弹提示，不抢页面。后端目前串行：有任务运行时只是不能开始新的模型任务，浏览和编辑不受影响。
