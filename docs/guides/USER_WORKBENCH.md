# 使用 MASA 项目工作台

在仓库根目录启动：

```powershell
.\.venv\Scripts\python.exe -m masa ui --port 8765 --open
```

浏览器打开 `http://127.0.0.1:8765`。若重构前的服务仍在运行，先关闭旧服务再启动；前端改动后在 `frontend` 执行 `npm run build`，刷新页面。

1. 点击「API 管理」，添加提供商、Base URL、模型与密钥。启用本地保存后重启可复用；输出 token 应足够容纳整套代码。
2. 点击「新建项目」，选择已配置 API，填写用途、输入输出和边界，点击开始。
3. 图上观察 Planner / Tester 的真实调用状态。图下查看结构化结果，修改规格和验证说明，然后「确认方案并生成代码与测试」。
4. Developer 完成后逐文件查看代码。点击「批准整套代码并验证」后，系统创建项目文件夹并运行真实 Go 检查。
5. 查看 Executor 和 Gate 状态、检查输出；「打开代码文件夹」定位文件。「重新验证」创建新的验证记录；可继续暂停的验证。
6. 失败时可使用受控修复，审核修复代码后再次验证。测试和模块保持冻结，不能通过删除失败断言来伪造通过。

左侧按项目显示，底部「版本记录与执行日志」可切换历史、读取并复制整体日志。日志是所选版本来源链的有界汇总；修复的新分支需要选择对应版本。

当前支持标准库 Go CLI 项目，3–20 个计划文件。这里的「验证」是 test / vet / 格式检查；输入参数并启动生成应用的入口仍在下一阶段。角色图会随真实事件更新，但还不是完全自主生成的任意 Agent Graph。运行中的模型调用不支持断点续传；关闭服务前应等待调用结束。
