# 使用 Planner 规划项目

打开 http://127.0.0.1:8765 并完整刷新。在 API 管理中选择配置、输入当前会话密钥，然后点 **规划新项目**。

输入具体用途、输入输出和边界条件。例如：

> 构建 CSV 统计 CLI，指定一个数值列，输出计数、最小值、最大值和平均值。空值跳过，非法数字返回行号，空文件和不存在列有明确错误。仅使用 Go 标准库。

一次规划最多调用模型两次：

1. Planner 提出简洁结构：设计理由、模块名、文件路径/职责、可测试验收项。
2. Runtime 校验规格后，Tester 根据同一规格给出 test/vet/格式检查目的，并覆盖所有验收项。

返回后在工作台查看方案。可以修改设计说明、模块名、文件路径/职责、验收文字和验证策略；点击 **确认当前项目方案**。确认绑定完整可见内容，随后只读，不能把修改后的内容套用旧批准。重新规划可从顶部创建新方案；暂不支持自动继承反馈。

确认不生成代码、不执行工具。当前 run 仍暂停，代表等待下一阶段 Developer；图中的检查是预留计划，不是已执行结果。服务只创建用于现有 Runtime 记录的占位模块，不生成目录树中的实现文件。

如果 Planner 输出非法路径、缺测试文件、格式错误或输出被截断，规划失败，不会继续 Tester。Tester 失败时仍可查看已保存的 Planner 方案。失败原因在方案页；请求/响应和用量在执行过程中的 Agent 决策。不会自动重试付费调用。

重启后需重新输入密钥；方案和审批保存在本地，刷新可恢复。未确认的本地编辑没有自动保存。没有验收测试实际执行前，不显示项目验证成功。
