# 模型路由与任务预算（M0）

目的：大部分工作让本地模型做，做不好才升级到更强的 API 模型，并且给整个任务设一个花费上限。设计与限制见 [进展008](../progress/PROGRESS_2026-10-03_008_m0-routing-and-budget.md)。

## 怎么用

1. 在「设置 → 模型配置」里配置模型，并设置**等级**：本地小模型设低（默认 1），强模型设高（云端默认 2）。等级由你指定，系统不会自动评测能力。同等级时按优先级（数字小的先）。
2. 新建任务，执行方式选「**自动执行**」，策略选「**本地优先 · 有界升级**」。可选填「API token 上限」（默认 200,000）。
3. 任务结束或随时点顶栏「任务报告」，看“路由与预算”。

「固定模型」仍是默认：整个任务只用你选的那一个模型，没有预算、没有升级，行为与以前完全一致。逐步确认模式不使用路由。

## 它怎么决定用哪个模型

- 每个阶段（规划 / 生成 / 修复）开始时，选**满足条件的最低等级**模型。
- 同一等级的模型最多尝试 N 次：规划、生成各 2 次（初次 + 带原因的自修），修复 1 次；仍失败才升级到更高等级。
- 已经在最高等级就不再升级，只受“最多 4 轮修复”约束。
- 最多升级 2 次。
- 以下情况会**停止**而不是继续花钱：预算用完、没有更高等级、输入放不进任何候选的上下文、设置了费用上限但候选没价格。停止时已有代码和失败证据全部保留，报告里写明原因。

不会触发升级的情况：配置、鉴权、网络问题；结果未知的请求（不会为了“换个模型试试”而掩盖它）。

## 预算怎么算

| 项 | 默认 | 说明 |
|---|---|---|
| 模型调用 | 40 次 | 本地与 API 都算 |
| API token | 200,000 | 调用前按“输入估算 + 输出上限”预留；用量没返回的调用按上下文上限计入，**不当作 0** |
| 运行时间 | 60 分钟 | 模型 + 工具耗时，不含等你确认的时间 |
| 费用 | 不限 | 需要给模型填价格；没价格的 API 模型会被排除 |

预算是**整个任务**的，修复和重规划都不会重置。

## 在报告里看什么

- **预算条**：越接近上限越红。
- **升级链**：每次决策用了哪一级哪个模型、为什么（“同级再试”“升级到更高等级”“已在最高等级”）。
- **停止原因**：如果因预算或等级停止，会有醒目的提示。
- 其余：按模型 / 按步骤 / 逐次调用的 token 与耗时、工具调用。

## 注意

- 本地模型的权重摘要在任务开始时记录；**恢复任务时**如果发现本地模型被替换过，该模型会被视为不可用（Ollama 不可达时不检查）。
- 输入大小是**估算**（每 token 约 2.5 字节），用来避免明显放不下的调用，不等于服务端实际不会截断。
- 想复验真实升级而不占 GPU，先看 [进展008 §6](../progress/PROGRESS_2026-10-03_008_m0-routing-and-budget.md)。
