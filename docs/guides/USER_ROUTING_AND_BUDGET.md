# 模型路由与任务预算（M0）

目的：大部分工作让本地模型做，做不好才升级到更强的 API 模型，并且给整个任务设一个花费上限。设计与限制见 [进展008](../progress/PROGRESS_2026-10-03_008_m0-routing-and-budget.md)。

## 怎么用

1. 在「设置 → 模型配置」里配置模型，并设置**等级**：本地小模型设低（默认 1），强模型设高（云端默认 2）。等级由你指定，系统不会自动评测能力。同等级时按优先级（数字小的先）。
2. 新建任务，执行方式选「**自动执行**」，策略选「**本地优先 · 有界升级**」。可选填「API token 上限」（默认 200,000）。
3. 任务结束或随时点顶栏「任务报告」，看“路由与预算”。

「固定模型」仍是默认：整个任务只用你选的那一个模型，没有预算、没有升级，行为与以前完全一致。逐步确认模式不使用路由。

## 它怎么决定用哪个模型

- 每个阶段（规划 / 生成 / 修复）开始时，选**满足条件的最低等级**模型。
- 同一等级的模型最多尝试 N 次：规划、生成各 2 次（初次 + 带原因的自修），修复 1 次；仍失败才升级到更高等级。
- 已经在最高等级就不再升级，只受“最多 4 轮修复”约束。
- 最多升级 2 次。
- 以下情况会**停止**而不是继续花钱：预算用完、没有更高等级、输入放不进任何候选的上下文、设置了费用上限但候选没价格。停止时已有代码和失败证据全部保留，报告里写明原因。

不会触发升级的情况：配置、鉴权、网络问题；结果未知的请求（不会为了“换个模型试试”而掩盖它）。

## 预算怎么算

| 项 | 默认 | 说明 |
|---|---|---|
| 模型调用 | 40 次 | 本地与 API 都算 |
| API token | 200,000 | 调用前按“输入估算 + 输出上限”预留；用量没返回的调用按上下文上限计入，**不当作 0** |
| 运行时间 | 60 分钟 | 模型 + 工具耗时，不含等你确认的时间 |
| 费用 | 不限 | 需要给模型填价格；没价格的 API 模型会被排除 |

预算是**整个任务**的，修复和重规划都不会重置。

## 在报告里看什么

- **预算条**：越接近上限越红。
- **升级链**：每次决策用了哪一级哪个模型、为什么（“同级再试”“升级到更高等级”“已在最高等级”）。
- **停止原因**：如果因预算或等级停止，会有醒目的提示。
- 其余：按模型 / 按步骤 / 逐次调用的 token 与耗时、工具调用。

## 模型与次序、API 账户、预检（2026-10-04 新增）

- **模型与次序**（新建任务页的「模型与次序」按钮，或 设置 → 模型与次序）：拖动行、点 ▲▼、或直接改“位置”数字调整尝试顺序；勾选决定本任务用哪些；每行可改等级（同级轮换，更高等级才算升级）；「严格按顺序」让每个模型独立一级。
- **API 账户**（设置 → API 账户）：一把 key 往往能用多个模型。页面向官方实时查询可用模型，**勾选即启用**（没有配置会自动添加），并排对比上下文、最大输出、图片输入、推理档位、建议价格；可查询余额（DeepSeek）。key 只在后端，页面从不显示。价格是官方文档的建议值，请核对。
- **预算与策略默认值**（设置 → 路由与预算）：可编辑并保存；每链尝试次数、最多升级、按角色起始等级、预算（调用次数、API token、运行时间、费用）。
- **可行性预检**：新建任务输入时实时检查。「确定会失败」（非 Go、第三方依赖、网络/数据库、GUI/硬件、要库而不是命令行）会禁用开始按钮并给出改写建议，勾选「我了解风险，仍然继续」才可开始；被拦下的需求**不调用任何模型**。「有风险」只提示。本地模型会再复核一次，**只提示、不拦截、不用 API**。
- **崩溃与服务重启**：本地模型服务被杀/重启时，任务会等服务恢复后自动重试（不算失败、不触发升级）；任务进程崩溃遗留的本地请求，恢复时会重试。**付费云调用永远不会被自动重放。**
- **卡死检测**：同一个失败（编译/测试诊断去掉文件名行号后相同）连续出现 4 次，且最强的模型也试过，就停下交给你。
- **孤儿显存**：杀掉 `ollama serve` 会留下继续占显存的 `llama-server` 孤儿进程。设置 → 本地运行时 的“模型运行进程”会检测并可一键清理（只清确认是孤儿的 Ollama 运行进程）。

## 注意

- **本地模型的输入超过上下文窗口时，Ollama 会静默截断（不报错）。** 系统在发请求前用估算拦截“几乎一定溢出”的输入：路由模式下会改用窗口更大的候选或停止；固定模式会明确报错。云端模型不拦（它们会自己报错）。
- **崩溃恢复**：已完成的模型调用不会重复；正在进行、结果未知的请求不会被悄悄重放，任务会明确停下并说明原因；被中断的验证会自动重新验证。

- 本地模型的权重摘要在任务开始时记录；**恢复任务时**如果发现本地模型被替换过，该模型会被视为不可用（Ollama 不可达时不检查）。
- 输入大小是**估算**（系数来自真实调用拟合：ASCII 约 3.6 字符/token，中文约 0.54 token/字符），用来避免明显放不下的调用，不等于服务端的真实分词。
- 复验真实升级：`scripts/e2e_live.py --routing ladder --keep <本地id>,legacy`（会占用 GPU，跑完记得卸载模型）。
