# 评测使用指南

用来回答一个问题：**我刚改的 runtime，让系统变强了吗？** 设置 → “评测” 一键运行，或命令行 `python scripts/bench.py`。

## 1. 它测什么

- **17 个 Go 命令行任务，10 个难度等级（L0–L9）**：从“打印一行”（L0）到“自己实现正则引擎”（L9，目前的模型多半做不出来，用来看上限）。等级表见设置页或 `src/masa/bench/tasks.py`。
- **独立判官**：每个任务有 Python 参考实现；系统生成的程序被**真的构建并运行**，逐用例比对输出与退出码。判官不读系统的测试，也不信系统的 Gate。
- **假通过**：系统的 Gate 通过了，但判官发现输出不对。这是对“证据驱动”最直接的检验——证据只和系统自己生成的测试一样可靠。第一次真实评测就抓到一个：`hello` 多打印了 `exit code 0`，系统自己的测试也照着这个误读写，所以 Gate 通过。

## 2. 套餐（都可以改）

| 套餐 | 任务 | 次数 | 默认上限（云端 token / 时间） | 用途 |
|---|---|---|---|---|
| 金丝雀 | L0–L2 共 3 题 | 1 | 12 万 / 15 分钟（实测约 5 分钟、5.7 万） | 一眼看系统是否还活着、有没有明显退步 |
| 快速 | L0–L5 的 6 题 | 1 | 40 万 / 45 分钟 | 看能力大致落在哪一级 |
| 标准 | L0–L6 共 13 题 | 2 | 150 万 / 3 小时 | 比较改动前后的通过率 |
| 完整 | 全部 17 题 | 3 | 400 万 / 8 小时 | 观察上限 |
| 自选 | 勾选任务 | — | — | 专门盯某个任务 |

## 3. 三层上限（评测会花钱，所以必须能卡住）

1. **单次运行**：云端 token、活跃秒数、调用数（路由层的任务预算，到顶就停并保留证据）＋ 一条硬性墙钟线（到点取消）。默认按等级给：时间 3–16 分钟、云端 4–17.5 万 token，可用“单次运行上限 %”整体缩放。
2. **整个评测**：云端 token 总量、总分钟数；到顶后剩下的运行标为“跳过”，统计里不含它们。单次运行的上限也会收缩到“整个评测还剩多少”。
3. **随时停止**：取消当前运行，剩下的跳过。

调度顺序是“先把每个任务各跑一遍（等级从低到高），再跑第二轮”——预算不够时，先保住低等级的数据，每个任务都至少有一次。

## 4. 怎么读结果

| 指标 | 含义 |
|---|---|
| 通过率 | 判官认可的运行 ÷ 已执行的运行（跳过的不计） |
| **稳定等级** | 通过率 ≥ 67% 的最高等级——**最推荐盯的一个数**，比“最高通过等级”不受运气影响 |
| 最高通过等级 | 至少通过过一次的最高等级（看上限） |
| 加权得分 | 权重 = 等级+1；高等级的通过更值钱 |
| 假通过 | Gate 通过但判官不认；应该趋近 0 |
| 每次通过的云端 token / 耗时 | 效率；改动是否让“同样的通过”更便宜 |
| **触发的 runtime 机制** | 自动修 import、语法门重写、Diagnoser、核对改判、整体重写、延长轮数、无改动拒收、转修测试各触发几次——**改动有没有在线上起作用的直接证据**。某项长期是 0，说明这个机制要么没被触发、要么没用 |

**如何判断“改动有效”**：同一套餐、同样的模型次序，改动前后各跑一次，在设置页“与之对比（基线）”里看稳定等级、通过率、每次通过的云端 token 的差值（绿=更好，红=更差）。每个结果都记录了代码版本（`提交` 一列，`+dirty` 表示有未提交修改）。**单次差异不可靠**：一个任务的通过率可能在 0%–100% 间波动，至少用“标准”套餐 × 2 次再下结论。

## 5. 注意

- **评测不能与正在执行的任务同时运行**（占用 GPU 和云端额度）；评测中新建任务会被拒绝。
- 评测在 `.masa/bench/state/<id>` 这个临时目录里跑，**不写入你的历史**；全部通过就自动清理，**有失败时保留账本（只留最近 3 份）**，方便用 `scripts/show_failures.py .masa/bench/state/<id> <run_id>` 排查；run_id 在结果 JSON 里。结果保存在 `.masa/bench/results/<id>.json`（不进 git）。
- 评测使用设置里**已启用**的模型与次序；命令行可用 `--models id1,id2` 限定。
- 判官会在本机构建并运行生成的小程序（10 秒超时、临时目录、精简环境变量），与系统自己的 runner 隔离强度不同——评测任务都是纯标准库的小程序，不要把它指向不可信的输入。
- 云端价格按模型单价估算，价格没配置时 `cost` 为“未知”，token 数仍然准确。

## 6. 命令行

```bash
python scripts/bench.py --list                                   # 任务与套餐
python scripts/bench.py --suite canary                           # 金丝雀
python scripts/bench.py --suite quick --repeats 2 --total-tokens 350000 --total-minutes 50
python scripts/bench.py --tasks hello,wc --repeats 3             # 自选，重复 3 次
python scripts/bench.py --compare <旧id> <新id>                  # 两次结果的差异（JSON）
```

## 7. 加一个任务

在 `src/masa/bench/tasks.py` 里加一个 `Task`：题面（把输入输出写精确，但保持用户平时的口吻，不暗示实现方法）、用例 `(args, stdin)` 列表、Python 参考实现 `ref(args, stdin) -> (stdout, exit_code)`，并在 `tests/test_bench.py::ReferenceTests` 里用**手算的答案**钉住参考实现（期望由参考实现算出，所以参考实现本身不能错）。等级要按“目前的模型多半能/不能做出来”放，相邻等级之间要有区分度。
