# MASA 功能优先级与分阶段实施表

v0.3 / 2026-09-26。用户已认可规划方向；本轮仍只整理文档。后续用户要求开始实现时，从 P0 开始，不把“认可规划”当作已完成实现。

## 1. 优先级规则

| 优先级 | 意义 | 可以停止在哪 | 不能声称什么 |
|---|---|---|---|
| P0 框架必须 | 最小运行链、清楚边界、图/状态/工具/模型接口 | 可运行的单步骤框架 | 已完成多 agent 或自优化 |
| P1 核心 demo 必须 | Go 仓库证据驱动的多角色修复、受约束适应、验证 | 完整且有辨识度的个人 demo | 已学习出更优跨任务策略 |
| P2 优化增强 | 经验复用、模型路由、离线策略晋升、通信优化 | 自优化实验版 | 普遍最优、生产效果已证实 |
| P3 可选/不做 | 按实测瓶颈和岗位价值选做 | 不影响核心项目交付 | 未实现的研究和部署能力 |

正确性不是 P2：版本核对、预算、真实工具结果、权限、必要恢复不能为追求效果被跳过。实现可以分步，但未完成边界必须显式限制功能。

| RL/训练 router、自由图搜索 | P3 | 无默认实施 | 有数据与实验预算再讨论 | 当前不做 |
| Redis/MQ/gRPC/登录 | P3 | 无 | 多用户或分布式时再设计 | 当前不做 |

## 3. 新任务编号与状态

使用 P0-01 等作为唯一当前任务 ID，状态存 [STATUS_PROJECT](STATUS_PROJECT.md)，这里不重复维护完成状态。旧详细文档的 R01/G03/A02 等是历史子任务参考，不能覆盖本表的顺序。

一轮会话建议完成一个任务或一个可验收子任务；若任务太大，用 P1-03a 这样的子编号在状态文件登记。实现顺序由依赖决定，不按文件数量或目录完整程度验收。

P1 出口：真正修改并验证一个 Go 仓库，能解释为何看这些代码、为何重规划、为何拒绝旧证据。没有证明成功率提升也可以交付机制完整的 demo，必须公开失败和费用。

P1-04a 已完成只读角色 envelope、权限、定向交接和 receipt 恢复。它使用 scripted，不开放 Developer 写入。P1-04 仍 in_progress，下一项 [P1-04b](PLAN_P1_04B_CONTROLLED_REPAIR.md) 接入语义输出与一次受控修复。

2026-09-27 用户要求优先真实 LLM 验收：拆出 **P1-06a**，仅依赖当前 AgentLoop、Tools、Context，已接入 DeepSeek V4 Pro 并验证成功/失败路径。P1-06 保持 in_progress，四角色接线仍等 P1-04；不因此宣称 P1-04、P1-05 或完整修复验收完成。后续首先回到 P1-04。

隐藏验收由外部 harness 持有，编码 agent 不可读取。只有普通测试通过时称“Gate 通过”，不能与外部验收结果混淆。

## 6. P2：按证据选择优化，不把清单全做一遍

| ID | 任务 | 依赖/触发条件 | 验收与退路 |
|---|---|---|---|
| P2-01 | Experience 检索与策略候选 | P1-08；有可用历史或明确 seeded 演示 | 前提过滤、反例、候选不直接执行；无匹配回默认 policy |
| P2-02 | 规则 Model Router | P1-08；配置了相容模型且有对比预算 | 选择理由、能力过滤、一次升级、重建上下文、不重放工具；可回单模型 |
| P2-03 | 离线 Self-Optimization Loop | P2-01；有冻结的开发/验证/测试划分 | shadow→对照→策略版本→回退；自动晋升默认关闭；差样本不晋升 |
| P2-04 | 通信 delta 与模型摘要 | P1-08；测得重复材料明显 | 基线缺失可重建；约束不丢失；实测 token/质量收益；否则保留完整有界交接 |
| P2-05 | 增量索引与缓存 | P1-08；全量索引有明显成本 | 增量/全量等价、失效正确、实测延迟收益；否则使用全量 |

P2-03 是项目自优化目标的核心；P2-02/04/05 是可独立选做的优化，不是其全部前置条件。第一次策略实验可只优化“跨包任务先检索调用方还是直接开发”，保持模型和其它策略不变。

2026-09-26 用户明确要求前端，并允许 React，因此提前安排独立增量 UI-01，不阻塞或重排 P1 核心任务。

|---|---|---|

架构与接口见 [DESIGN_LOCAL_CONSOLE](DESIGN_LOCAL_CONSOLE.md)，使用见 [USER_CONSOLE_GUIDE](USER_CONSOLE_GUIDE.md)。

不默认安排在线 RL、模型训练、任意代码生成工作流、自动修改 runtime 自身、Agent Marketplace、Kafka/Redis、登录系统。这些项目名词不会自动增加简历价值。

## 9. 停止、降级与重构规则

如果时间不足，优先交付 P0 或 P1 的真实可运行版本，报告未完成项；不要用 mock 输出代替真实成功。遇到模型 provider 未配置，继续 scripted 机制测试与文档，真实效果标 blocked，而不是阻止全部开发。

重构保持 GraphSpec、EvidenceRef 与 Tool 协议行为兼容；schema 变化写 migration/版本说明并测试恢复。内部目录和类可以调整，不要求僵硬照抄建议文件树。每轮范围不自动扩展到下一优先级。
