# 长期路线与优先级

2026-09-28 重排：先清晰工作台与可用闭环，再扩大自治能力。

| 优先级 | 阶段 | 目标 / 验收 | 当前状态 |
|---|---|---|---|
| P0 | R1 架构重组 | 职责分目录，角色契约与传输分离，旧证据可读 | 已实现 |
| P0 | R2 项目工作台 | 单一开始入口、真实角色状态、人审、版本与日志 | 已实现；浏览器视觉验收待补 |
| P0 | D1/D2 应用运行 | 在前端向生成 CLI 传 argv，运行/停止并观察实际输出 | 下一阶段 |
| P1 | R3 统一角色调度 | 规划/生成成为持久节点，重启恢复待审核阶段，角色图与调度共用状态 | 未实现；当前为事件投影 |
| P1 | R4 更合理验证 | 独立业务场景、Reviewer 证据审查、明确测试覆盖局限 | 部分实现 |
| P1 | I2 上下文与代码理解 | 生成/修复消费有来源的相关代码与失败摘要，测量上下文成本 | 已有基础索引，待接入更多用例 |
| P2 | G2 有界自适应图 | Planner 提议依赖；Runtime 校验 DAG/预算；失败可增加受限节点 | 部分检查计划可变，任意角色图未实现 |
| P2 | M2 经验优化 | Task/Graph/结果/成本/策略入经验，检索改善后续规划，基线对比 | 仅基础记忆，不是自主学习系统 |
| P2 | Model Router | 按复杂度和风险选模型，衡量质量与费用 | 先手动 API 选择，不急于自动路由 |
| P3 | 平台化 | 容器隔离、多租户、远程执行、分布式调度 | 可选，个人 demo 暂不需要 |

Go 继续负责进程执行、资源边界和 Go 代码索引；Python 负责角色与 Runtime；React 负责观察和人审。动态节点不意味着放开工具许可，测试通过也不意味着业务需求全部正确。
