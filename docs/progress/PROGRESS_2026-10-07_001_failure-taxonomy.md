# 失败分类（工具方向的第一步：只读数据，0 token）

2026-10-07。`scripts/failure_taxonomy.py` 扫描 `.masa/**/bench/state/*/runtime.sqlite3` 里的评测账本（35 个任务账本，121 次失败的验证，263 条失败条目），按每条失败的诊断归类，并统计“下一轮缓解率”（下一次验证未解决条目变少或直接通过）与“任务终局里”（该任务最后一次验证仍在的条目）。分类是启发式的，见脚本顶部说明；“逻辑错/期望算错”靠后续修复的类型和 Diagnoser 的判断推断，所以其缓解率按定义偏高（逻辑 100%），**只看占比与“未解决”**。

## 当前系统（云端 Pro+Flash，p2eval 的 32 个账本，63 条）
| 类别 | 条目 | 占比 | 说明 |
|---|---|---|---|
| 期望算错 | 23 | 37% | 例：`Count("你好 世界\n") = (1,2,14), want (1,2,13)` ——字节/字符/单词计数 |
| 未解决的断言 | 32 | 51% | 修复后没有改善；多为同一类计数断言（`bytes = 5, want 4`）或 `Transport: 2.00` 这类格式 |
| 逻辑错 | 6 | 10% | 如 TopWords 分词语义 |
| 标准库用法错 | 1 | 2% | `csv.NewReader("")` 类型不对 |
| 其它（编译/模块路径/import/测试结构） | 0 | 0% | 云端强模型基本不犯 |
按任务看：**63 条里 36 条来自 wc（字节/单词计数）**，其余零散分布在 wordfreq、csv_sum。

## 旧账本（3 个评测账本，混合本地小模型 + 云端，201 条）
编译/接口类很多：项目内部接口对不上（internal_api）19%、语法 12%、模块路径 7%、标准库用法 5%、import 2%；这些在升级到云端后大多一轮内缓解（53%–78%）。期望算错 10%，逻辑错 19%，未解决 23%。

## 对“要不要做 go doc / 算期望值工具”的含义
- **`go doc`（标准库用法）**：数据不支持。当前云端配置里标准库用法错只占 2%（1 条）；旧账本里 5%，主要是本地小模型，已被升级机制和 goimports 覆盖。
- **算期望值**：数据支持，但**很窄**——期望算错 + 未解决的断言合计约 88%，其中大头是“数字符串的字节/字符/单词数”，集中在 wc 这一类任务。一个确定性的“字符串度量”工具（按 Go 语义算 `len([]byte)`、`utf8.RuneCountInString`、`strings.Fields`、换行数）能直接核对这类期望；对其它类型的期望（排序、分词语义、格式）帮不上。
- 局限：样本只有 ~12 次失败的验证（云端）、集中在少数任务；分类是启发式的。
