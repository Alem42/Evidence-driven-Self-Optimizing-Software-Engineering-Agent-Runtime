2026-10-05。分支 `feature/multi-model`。前置：[进展014](PROGRESS_2026-10-04_006_diagnoser-checks-rewrite-leaks-testlint.md)。使用说明：[USER_BENCHMARK](../guides/USER_BENCHMARK.md)。

## 1. 做了什么

| 块 | 内容 |
|---|---|
| 任务库 | `masa/bench/tasks.py`：**17 个任务、10 个难度等级（L0–L9）**；期望输出由 Python 参考实现算出（不手写），参考实现本身用手算答案钉住（`tests/test_bench.py`） |
| **独立判官** | `masa/bench/oracle.py`：把系统生成的项目**真的构建并运行**，逐用例比对输出与退出码；不读系统的测试、不信系统的 Gate。系统 Gate 通过但判官不认 = **假通过** |
| 三层上限 | 单次运行（路由层预算 + 硬性墙钟线）；整个评测（云端 token 总量、总分钟数，到顶后剩下的“跳过”）；随时停止。调度“先每个任务各一遍、等级从低到高”，预算不够时先保住低等级数据 |
| 指标 | 通过率、**稳定等级**（通过率 ≥ 67% 的最高等级）、最高通过等级、加权得分、假通过、每次通过的云端 token/耗时、各 runtime 机制触发次数 |
| 一键运行 | 设置 →“评测”：套餐（金丝雀/快速/标准/完整/自选）、上限可改、实时进度、按等级与按任务的结果表、历史结果、**与基线对比**；命令行 `scripts/bench.py` |
| 隔离 | 评测在临时状态目录里跑，不写入历史；不允许与正在执行的任务同时运行；**有失败时保留账本**（最近 3 份） |

测试：Python 377 项（新增 `test_bench` 23 项），前端 31 项。

## 2. 评测当场抓到的问题（这就是它的价值）

1. **假通过**：第一次真实评测里 L0 `hello`（“打印一行 hello, masa……退出码 0”）被系统判为通过，判官发现程序多打印了一行 `exit code 0`——模型把“退出码 0”当成要输出的文字，系统自己生成的测试照着误读写，Gate 通过。**修复**：Planner 提示词要求把目标里的字面输出/格式/退出码原样写进验收项，并明说“退出码是进程状态，不是要打印的文字”。修复后 `hello` 多次评测全部通过，假通过为 0。方案已记入 PLAN_LOW_MODEL_QUALITY #15（需求→验收项→测试的忠实度，M3 追溯矩阵）。
2. **鲁棒性**：`wc` 一次失败——修复实现的模型反复想改冻结的测试，被校验拒绝，整个任务失败。**修复**：这种情况视同“最强模型认为问题在测试里”，转去修订测试一次（`repair_wants_tests` 事件），修复前确认会失败的回归测试。
3. **可观测性**：失败的评测账本随临时目录清掉了，没法排查 → 现在保留。

## 3. 第一批基线（**纯云端**：deepseek-flash → deepseek-v4-pro，不用本地模型；提交 `8fc3867`）

> 本地模型的基线按你的要求**之后再补**（GPU 被你占用）。下面的数字只代表“云端两级”的能力。

| 评测 | 运行 | 通过 | 假通过 | 稳定等级 | 云端 token | 耗时 |
|---|---|---|---|---|---|---|
| 快速 ×2（L0–L5，6 题） | 12 | **11（92%）** | 0 | L5 | 20.2 万 | 6.7 分钟 |
| 标准 ×1（L0–L6，13 题） | 13 | **12（92%）** | 0 | L5（L6 为 50%） | 23.6 万 | 8.6 分钟 |
| 高等级 ×1（maze、calc、topo、kvtx、regex） | 5 | 3 | 0 | L8 | 21.4 万 | 7.1 分钟 |
| maze 复现 ×2 | 2 | 2 | 0 | — | — | — |

**读数**：
- **L0–L5 对云端模型已经饱和（几乎 100%）**，区分不出 runtime 改动的好坏——要观察改动，必须用**本地模型**或更高等级。
- **L7（calc、topo）和 L8（kvtx）云端能做出来**，上限在 L9。
- **失败的类型**：① `regex`（L9）死在**生成阶段**——“模型输出被截断”（云端一次生成所有文件，超过输出上限）。这是**系统限制，不是模型能力**：云端也应该逐文件生成。② `maze`（L6）**不稳定**（4 次里 2 次通过；失败时 Gate 不过，不是判官）；失败证据已丢（见 §2.3）。③ `wc` 一次（已修）。
- **真实触发的机制**：自动修 import、Diagnoser、延长轮数、**整体重写**（maze 上首次在线上触发，但没救回来）。核对改判（reconciled）和转修测试在这批里没有触发。
- **成本**：纯云端平均每个任务约 1.8 万云端 token、40 秒。混合模式（本地起步）的对照等本地评测能跑时再测——那才能回答“云端 token 降低多少”。
