# 前端重构：任务工作台

## 为什么重做

上一版只是把原页面挤进“代码中心 + 底部输入框”，实际上所有审核、结果、日志仍纵向堆叠。底部框不可输入时占空间；角色图浮层与页面滚动让操作位置难找。本轮改为独立信息区域，不再靠更多折叠卡片解决层级问题。

## 新的使用方式

左侧搜索和选择项目；中央顶部固定四个入口；右侧实时执行状态。新建项目只需需求、模型、执行方式，然后开始。进入项目后需求表单退场，底部只保留短状态条，不伪造尚未实现的聊天能力。

| 入口 | 你在这里做什么 |
|---|---|
| 当前任务 | 回答澄清、确认方案、审核/编辑草稿、修复、运行已通过的程序 |
| 代码 | 文件列表与完整只读草稿/批准快照；不是可变工作区内容 |
| 验证 | 单独看真实 test/vet/格式结果；规划时说明尚未执行 |
| 日志与版本 | 读取/复制日志、切换历史、展开实际角色调用 |
| 状态侧栏 | 看当前等待类型、角色时间线、展开原始需求 |

成功验证默认打开代码；其他阶段打开当前任务。手动切标签后轮询不抢回。执行期间手动选历史，也不会被轮询抢回；需要跟随时用“返回执行中的项目”。小屏将右侧改为紧凑顶部状态；手机布局保留内容导航。

API 管理保留导入、配置编辑、密钥保存/清理、删除与连接测试。高级调用参数和维护操作收起，连接测试明确标注调用 API。新增配置默认输出上限8192，已有配置不改。弹窗支持 Escape、键盘焦点循环和关闭后返回入口；忙碌期间不能隐藏请求。

## 代码组织

App 装配导航、新建与三栏布局；useWorkbench 负责轮询，并新增“跟随执行/手动查看”选择；ProjectDetails 按标签组织业务组件；RuntimeRail 只展示后端事实；CodeSnapshot 统一草稿与快照浏览；workspaceState 是可测试的纯展示策略。现有规划、代码审核、修复与运行组件继续调用原接口。

删除 RoleGraph 的横向卡片组件。CSS 全部重写为统一布局与组件样式，删除旧图、旧底部框和覆盖规则。没有新增 UI 框架，没有新 Runtime 状态或权限，没有把 UI 的状态选择写回后端。
