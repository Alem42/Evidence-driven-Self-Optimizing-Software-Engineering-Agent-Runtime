# 测试构建目录与常量溢出修复

用户反馈：新生成的随机数项目在 CLI 集成测试中失败，整数求和项目也无法验证。本轮修复这两份实际项目及通用错误分类，并提供手动验证方式。

## 原因和结果

| 项目 | 原运行 | 根因 | 新的成功运行 |
|---|---|---|---|
| 随机数 | `f996f79f5b804a3186b346a99681622a` | `cmd/app` 测试设置 `cmd.Dir=".."`，去没有 Go 文件的 `cmd` 构建 `.` | `68e1db6c7bf04cba8e7952b3f8e9ff68` |
| 整数求和 | `53dc4c7efdd34041b5abaa8e86620c17` | 测试切到模块根目录仍构建 `.`；两处期望值常量 `maxInt+1` 编译溢出 | `52d50f2b865d481f98bf105d3b90ef6b` |

这次不是缺 `io`。两份项目都使用真实 DeepSeek 生成测试修订草稿。审核时发现模型删除了与修复无关的注释和整数项目 `TestMain`，后者会造成 `os` 未使用；采用版本恢复这些无关改动，仅保留路径修复和可表示的最小整数期望值。未修改产品实现或删除行为断言。

两个新运行的 go test、go vet、格式检查和 Gate 全部通过。另将批准源码复制到 `.masa/manual-verification/<run-id>/project`，在同级编译 `app.exe`，直接调用验证：

- 随机数：默认输出在 0–99；`-min 7 -max 7` 输出 7；反向区间输出错误、stdout 为空、退出 1。
- 求和：空输入输出 0；`1 -2 3` 输出 2；`1 abc 2` 和 `0x10` 仅错误输出、退出 2。

手动副本不修改 Runtime 快照，不冒充新的 Gate 记录。操作与详细环境说明见 [Go 环境与手动验证](../guides/USER_GO_ENVIRONMENT_AND_TESTING.md)。

## 平台修复

- 补齐测试构建路径、未使用变量、常量溢出的测试修订分类。
- 按 Go JSON 输出中的实际诊断行匹配，避免把某行测试断言和另一行实现缺 import 混合误判。
- `/results` 返回统一 `repair_advice`，前端和自动模式采用同一分类。测试准备错误默认强调测试修订，禁用无法修改测试的实现修复按钮。
- 失败摘要保留 `no Go files in ...`；生成与修订提示明确包工作目录、正确构建目标、整数常量范围及 `io.Writer`。

验证：111 个 Python 测试、4 个前端测试、Vite 构建通过；两份真实 LLM 修订经过全部 Go 检查。8765 服务重启后 HTTP 验证旧版本均推荐 `revise_tests`、新版本均 succeeded，并确认正在提供新版 JS。本轮没有浏览器视觉/点击自动化验收。

## 环境答疑和后续

实测工具链为 `.tools/go` 中的 Go 1.27.1 Windows amd64。当前 runner 禁止自动下载工具链和模块，不自动运行 go get、go mod tidy 或 goimports。缺 import 会在编译时报告，模型可能在修订中修复；这不等同于安装依赖。

缓存变量来自允许的父环境：激活脚本设为 `.cache`，不激活时可能落到用户目录。当前工作区和进程生命周期有隔离，但没有完整文件/网络沙箱。详细边界和后续环境预检、导入整理、显式依赖准备的顺序已写入指南及下一阶段文档，未宣称这些已经实现。
