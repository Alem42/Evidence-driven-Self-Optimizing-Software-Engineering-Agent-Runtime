## 流程修复

- 失败证据抽取保留关键 Go 诊断，而不是只截取输出末尾。
- 只有测试文件格式失败时，无模型调用地以 `gofmt` 生成新的、可审核的测试版本；测试断言不改动。
- 同一条 Go 断言连续三次失败时，自动修复停止并提示核对规格与测试，避免 Developer 为迎合矛盾测试修改正确实现。语义矛盾仍需明确的测试修订，不能由 Runtime 自动删改断言。
- 小任务 Planner 优先 4–8 条验收项，Tester 明确使用有效的零基编号，避免简单任务失控。
