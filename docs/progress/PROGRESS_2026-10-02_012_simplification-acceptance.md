# 架构减法与真实随机数验收

## 做了什么

保留一条项目路径，删除前端检查图和布局算法；它只是固定检查汇总，继续展示没有帮助。后端 Graph 仍调度 test/vet/format 并向 Gate 提供证据。角色记录折叠到顶部，代码占中央，底部需求框一直显示；已有项目与运行期间不允许提交新需求，澄清仍有专门入口。详细输出、运行应用和历史日志按需展开。

Runtime 写入明确 run_kind，读取旧记录时推导用途。工具执行在终态返回前校验用途，避免完成的语义评审被误当成验收。RoleRuntime 用事务迁移标记只搬一次旧角色调用。三个无当前引用的同名源码副本已从 src/masa 移出，.masa/legacy-backup 留备份；实际 Python 导入的是包。CLI demo 标 legacy；旧单文件、历史账本和快照兼容保留。

文档已收敛：STATUS 事实、PLAN 下一步、CURRENT 接续。旧路线与澄清方案归档，旧入口保留短指引。当前系统架构和工作台指南重写。详细路由与持续对话愿景单独在 PLAN_MODEL_ROUTING_AND_WORKBENCH，不混成已完成能力。

## 真实调用发现了什么

1. 首次生成测试遗漏 fmt，真实编译失败；自动建立测试修订。
2. 测试使用相对 exe，Windows exec.ErrDot 拒绝执行。原分类错送 Developer，冻结测试校验拦截；已修复分类与绝对路径提示。
3. 显式测试修订后又发现未使用 os，保留失败，新测试修订通过 Gate。
4. 独立探针仍发现 -seed 0 被当成未指定。没有修改旧快照或声称 Gate 保证业务正确；在新的方案中明确零种子边界。
5. 新方案的一次 Developer 响应为坏 JSON，记录失败并停止。后续显式新任务复用批准方案，而非隐式重放原请求。收到的坏 JSON 现在报告安全的行列位置，保留用量，不回显内容。
