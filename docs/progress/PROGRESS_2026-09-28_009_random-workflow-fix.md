# 随机数项目复盘与工作台修正

2026-09-28。针对用户随机数生成器项目，读取了完整来源链、模型事件和三轮 Go 工具输出，并沿真实失败证据逐次修复。所有失败、测试修订和最终成功版本保留在 `.masa`，未覆盖旧工作区。

## 到底为何失败

1. 初始 `61b8a48c`、`9df76dbb` 的 Tester 阶段是**测试方案生成**。模型给出的 `expected` 字段类型错误、随后用例集合越界，协议校验拒绝了方案；这些运行的 `test/vet/format/gate` 均为 pending，未执行 Go 测试。
2. 代码发布后的首个验证 `39b4ee14` 才真正运行 `go test`。`random_test.go` 导入 `cmd/app`，而 `main.go` 导入根包，Go 报 `import cycle not allowed in test`；初版实现还有未使用导入。
3. 普通修复冻结 `_test.go`，因此先前的两次 Developer 修复无法消除循环导入。新增专门的 Tester 测试修订，只改已有 `_test.go` 并发布新版本。
4. 测试修订依次暴露未使用 `os` 导入和 Windows CLI 测试的 `.exe` 后缀问题。修正后 Go 测试终于执行了行为断言，发现无参数运行返回 0 并输出随机数，违背已批准的“显示用法、退出 2”。
5. 最后一轮 Developer 只修改 `cmd/app/main.go`。验证运行 `4d162e1bf86043b58b4d0364d0fe793b` 的 `go test`、`go vet`、格式检查退出码均为 0，Gate succeeded。此结论限于当前测试覆盖。

## 这轮交付

- 角色图显示当前版本的一条主线，自动定位当前节点与操作区。方案的细节折叠，代码紧贴当前操作，失败只显示关键线索，完整日志仍可展开或复制。
- 验证阶段新增只读代码视图，直接读取该运行绑定的批准 artifact，可按文件切换；API 拒绝读取不属于该运行的任意引用。
- 新增明确的测试修订边界：测试修订只能改旧 `_test.go`，实现修复仍不能改测试。图和审核页区分 Tester 修订与 Developer 修复。
- 用户可在开始时选择自动模式：规划、生成、检查与最多四轮修复连续推进，最多 7 次模型调用。自动采用与人工批准在记录和界面中分开标示；Gate 始终依据真实检查结果。
- Windows HTTP 服务启用独占端口。诊断发现原来 `8765` 同时有两组进程监听，导致请求可能落到旧版后端；现已停止重复进程并只运行一个新版服务。

随机数项目的真实 DeepSeek 测试修订与实现修复已完成，最终 Go 检查全部通过。自动模式在离线提供商下从 HTTP 单请求推进到 Gate；105 个 Python 测试、4 个前端 Node 测试和 Vite 构建通过。新版本地服务的静态资源和最终角色视图通过 HTTP 检查。此环境的 computer-use 未提供浏览器会话，尚不能声明真实点击或视觉验收。
