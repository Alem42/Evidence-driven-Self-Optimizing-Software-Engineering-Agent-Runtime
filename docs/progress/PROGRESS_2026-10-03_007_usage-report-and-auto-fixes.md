## 1. Token / 耗时 / 工具调用报告

- 后端 `application/usage.py` 从已有事件（`model_requested` + `model_completed/failed`）与工具账本投影，**不新增状态**：`GET /api/projects/:id/report`。
- 覆盖同一任务版本链的所有版本。内容：结论（完成/未完成/取消/等待）、总耗时与模型耗时、总 token（输入/输出）、本地 vs API、按模型、按步骤、逐次调用时间线、工具调用（工具、结果、退出码、耗时、执行方式）。
- 缺失用量保持“未知”，不当作 0；只有请求没有结果的调用标为“未返回结果”。
- 前端：顶栏常驻 `Σ 总 token · 本地 · API` 芯片；任务结束（终态）自动弹出报告，等待你处理的状态不弹；顶栏「任务报告」可随时打开，支持复制为文本。

## 2. 自动化流程缺陷（用真实 DeepSeek 端到端复现并修复）

| 现象 | 根因 | 修复 |
|---|---|---|
| 测试/vet 已通过，却因 gofmt 失败反复“修复”4 轮后放弃（`changed=[]`） | 模型写出的代码不是 gofmt 格式，而格式是确定性工作 | 草稿/修复/测试修订产出时统一 gofmt（冻结文件不动）；仅 gofmt 失败时无模型格式化实现或测试文件 |
| 测试自身与已批准规格矛盾，系统却一直改实现 | 修订测试提示词只说“保留断言”；同一断言失败三次直接停 | 同一断言在一次实现修复后仍失败时，让 Tester 以规格为准仲裁一次；提示词明确“规格优先” |
| 规划/生成/修复响应被契约拒绝即整任务失败 | 无带原因的重试 | 响应已收到但被校验拒绝时，带具体原因重试一次（Planner 重规划继承已回答的澄清）；网络、鉴权、截断、取消不重试 |
| `go test` 才暴露的确定性错误 | 无预检 | 规格拒绝根目录 `.go` 文件；代码预检拒绝第三方 import、同目录混用包名 |

真实结果（DeepSeek，同一批需求）：随机数生成器、动态规划、背包、整数求和全部一次通过（此前同类需求连续失败）。“区间归并”在修复前因测试期望与规格矛盾失败，仲裁逻辑针对它；改动后未再复跑该需求。
