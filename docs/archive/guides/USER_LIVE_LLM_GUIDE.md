# 使用真实 DeepSeek 验证 Go 项目

现在可以在控制台管理多组 API，并让真实模型根据 Go 工具结果完成验证。当前仍是验证 Agent：代码生成、四角色协作和自动修复下一阶段继续实现。

## 启动与 API 管理

```powershell
.venv\Scripts\python.exe -m masa ui --port 8766 --open
```

本轮服务地址为 `http://127.0.0.1:8766`。如果已在运行，直接打开地址即可，不要重复启动同一端口。

打开「API 设置」：可添加、修改、删除配置、设为默认、清除密钥及测试连接。DeepSeek 使用以下参数：

| 字段 | 值 |
|---|---|
| Base URL | `https://api.deepseek.com` |
| 模型 | `deepseek-v4-pro` |
| 输出参数 | `max_tokens` |
| 思考模式 | 关闭（先验证接线） |
| 输出上限 | 本轮测试 512；界面新建默认 2,048 |

API Key 留空保存会保留当前会话已有密钥；服务重启需重新输入。更换 Base URL 会清掉旧密钥，避免误发。连接测试使用已保存参数，会产生一次模型调用；编辑参数后先保存再测试。

## 运行与观察

1. 新建任务，执行模型选「Live LLM」，选择有密钥的 API 配置。
2. 仓库可填 `E:\Project\AiAgent\Project02\tests\fixtures\go-complex`；勾选「完整验证图」及「Go AST / 代码证据上下文」。源码与工具日志中的部分内容会发送给选择的 API。
3. 默认自动继续，依次执行 test、vet、format、Gate。取消自动继续则首个验证节点后暂停。图上「继续时自动推进」决定下一次继续是单步还是执行剩余节点。
4. 「Agent 决策」查看 context、结构化提案、usage；「工具证据」查看真正的 stdout/stderr；「查看报告」汇总 provider 和实际返回的 tokens。失败、费用未知不会显示成成功或零费用。

三个验证节点使用同一个模型和快照，当前串行执行；图自动继续不意味着已实现自主规划。Gate 不调用模型，依据证据判定结果。完整图默认最多 8 次模型调用、6 次工具调用；AST 索引占用一次工具额度。

## 已跑过的真实验收

| 用例 | 结果 | 模型 / 工具调用 |
|---|---|---|
| 跨文件转账与批处理：边界、余额守恒、溢出、失败回滚；test + vet + fmt | succeeded | 6 / 4（含 AST） |
| 原始带缺陷的 Go Todo 项目 | failed，符合预期 | 2 / 2（含 AST） |

加上连接探测，共 9 次请求；输入 16,808、输出 438，合计 17,246 tokens。按峰时全输入未命中缓存 ¥9/百万、输出 ¥27/百万估算 ¥0.163098；这不是实扣账单，也不统计未来手动运行。

测试脚本 `scripts/smoke_live.py --port 8766` 会隐藏输入密钥、再运行同样的付费用例；不要把密钥写入命令参数。加 `--configure-only` 只注入本地服务配置，不调用模型。脚本结果保存在被 Git 忽略的 `.masa/live_smoke.json`；运行证据仍可从前端读取。

当前没有货币级硬预算，只有调用次数、输出上限、工具次数和时间预算。连接超时不会自动重试；取消不能撤回已经送出的 API 请求。遇到配置或协议错误先查看诊断，不要不断点击连接测试。
