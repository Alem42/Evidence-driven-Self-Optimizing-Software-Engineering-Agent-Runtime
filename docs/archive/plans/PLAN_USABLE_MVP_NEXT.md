# 下一阶段预计更新：围绕真实可用链路完善

按用户最新要求，路线改为“先能生成并验证真实代码”，不再等完整四角色自动修复协议实现后才交付。当前单文件生成 → 人工审核 → 受控写入 → Go 验证已经实测通过。

| 优先级 | 下一项更新 | 可验收结果 |
|---|---|---|
| P1 | 验证失败后的定向反馈 | 一键把真实失败日志和当前代码带到下一份草稿；仍需人工批准，最多一次显式重试 |
| P1 | 更清晰的审核页 | 真正的逐行 diff、人工编辑标记、生成/审核/验证耗时和模型实际 token 汇总 |
| P1 | 小型固定回归集 | 新函数、已有单文件缺陷、错误输入与生成截断；同时记录成功和失败，避免只看一个样例 |
| P2 | 小范围多文件修改 | 等单文件稳定后支持少量文件；继续复用当前补丁哈希与副本，不引入大型工作流框架 |
| 后置 | 四角色真实语义协作、动态图、自优化 | 保留已有只读角色和 receipt 基础，等实际复杂任务需要时再接入，不作为可用 MVP 的前置条件 |

下一轮先查看当前运行状态和本轮进展。不要重复花费模型额度跑相同成功案例。若做生成失败重试，必须显式记录新请求、关联旧 run，不静默自动付费重试。

继续保留：原仓库不变；人审前不执行生成代码；旧 proposal_ref 不能误批准；Go 工具失败时 Gate 不放行。完成下一项后照例新增进展报告和下一阶段预计更新 Markdown。
