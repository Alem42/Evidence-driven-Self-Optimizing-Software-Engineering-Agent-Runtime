# 项目长期约定

此文件是本仓库的持久记忆，后续 LLM 每次开始工作必须读取；它不是账户级记忆。

- 用户要求：先检查并妥善保存已有改动，每完成一个经过验证的独立增量，及时 `git commit`，便于回滚。不要只在会话最后提交；不要提交密钥、运行数据库、临时工作区或不相关改动。
- 函数功能与核心逻辑添加中英文对照注释。优先交付小而可用的纵向流程，避免为个人项目引入过重架构。
- 完成后更新状态、易读进展报告和下一阶段计划，所有项目 Markdown 放在 docs 中。
- 前端是主要使用入口；目标是自然语言生成完整 Go 项目文件夹，经人工审核后通过 harness 执行与验证，结果可观察、可追溯。
- 区分真实 LLM、脚本策略、测试通过与业务正确；不得将路线中的能力描述为已经实现。
- API 密钥只放服务会话内存，不写文档、代码、日志或 Git。真实付费测试按用户已授权预算控制，普通回归优先离线。
