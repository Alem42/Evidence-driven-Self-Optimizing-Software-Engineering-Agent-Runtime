# 项目长期约定

此文件是本仓库的持久记忆，后续 LLM 每次开始工作必须读取；它不是账户级记忆。

- 2026-10-03 用户再次授权大幅重构前端：当前采用项目历史、中央四标签、状态侧栏；新建需求表单仅新项目显示，已有项目底部为状态条。此项覆盖10-02“永久底部需求框”的布局约定。状态须区分需求澄清、审核、模型失败和真实工具失败；手动看历史不得被后台轮询抢回。持续对话仍是愿景，不做不能用的聊天框。

- 2026-10-02 最新方向覆盖旧图布局约定：执行架构减法，中央代码、紧凑顶部进度、底部固定需求框、侧栏历史；不用阶段跳转滚动整个页面。检查依赖图不再展示，底层调度/Gate保留。路由先按现有 Settings/Coordinator/RoleRuntime 扩展，禁止新重复状态体系、任意动态图和多 Agent 并发。具体见 PLAN_MODEL_ROUTING_AND_WORKBENCH。

- 用户要求：先检查并妥善保存已有改动，每完成一个经过验证的独立增量，及时 `git commit`，便于回滚。不要只在会话最后提交；不要提交密钥、运行数据库、临时工作区或不相关改动。
- 函数功能与核心逻辑添加中英文对照注释。优先交付小而可用的纵向流程，避免为个人项目引入过重架构。
- 完成后更新状态、易读进展报告和下一阶段计划，所有项目 Markdown 放在 docs 中。
- 前端是主要使用入口；目标是自然语言生成完整 Go 项目文件夹，经人工审核后通过 harness 执行与验证，结果可观察、可追溯。
- 区分真实 LLM、脚本策略、测试通过与业务正确；不得将路线中的能力描述为已经实现。
- 角色负责决策，检查节点负责具体动作；Runtime 校验计划与工具请求，Gate 独立核对真实结果。不得用 Agent 自称通过代替验收，不把 test/vet/format 当作三个决策 Agent。
- 2026-09-28 用户更新：允许 API 密钥保存到本地 Git 忽略文件，重启自动加载；禁止写入文档、代码、日志或 Git。关键功能优先真实 API 验收，预算仍按已授权范围控制；确定性边界回归保留离线测试，不无意义重复付费调用。

- 2026-09-28 架构约定：采用 domain/application/runtime/agents/intelligence/infrastructure/interfaces；React 采用 app/api/features。优先单一项目工作台，模型选择+描述+开始；角色图展示真实状态，结果与人审在下方。先可用闭环，再统一持久角色图，不引入过重平台。

- 2026-09-28 使用者反馈：图要自动定位当前节点，下面只保留当前阶段的关键结果和代码；需有一次授权后自动生成、运行 Go 检查并有界修复的模式。Tester 是测试方案角色，真实 go_test 只在项目代码发布后执行；Gate 只核对真实工具证据。随机数项目证明测试本身可能有导入循环，需独立测试修订，普通实现修复仍冻结测试。
