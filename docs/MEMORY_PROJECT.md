# 项目长期约定

此文件是本仓库的持久记忆，后续 LLM 每次开始工作必须读取；它不是账户级记忆。

- 2026-10-04：本地模型对超窗口 prompt 静默截断（实测），所以对本地模型在发请求前做硬拦截（只在下界估算仍超窗口时拒绝）；云端不拦。token 估算系数来自真实调用拟合，不要退回拍脑袋常数。验证真实升级用 scripts/e2e_live.py --routing ladder --keep <本地id>,legacy；跑本地模型前确认用户不占用 GPU，跑完卸载。每个新增回归测试都要确认修复前会失败。

- 2026-10-03 用户约定：①不要在提交里加 Co-Authored-By（已从历史中移除并强推）；②用户需要显卡时立即停止并卸载本地模型，之后只用 API/离线测试验证；③放行 httpx，引擎迁移用 Strangler，Worker 手动启动、崩溃可续跑即可；④M0 路由与预算已完成（进展008），真实本地→云升级端到端待补。

- 2026-10-03 方向（用户确认的理想形态是一张带“高级模型诊断”回路的图）：不推倒重来，不引入重型编排框架；在现有事件账本+内容寻址产物+角色调用账本上，按 M0 任务级预算与路由 → M1 声明式图/Diagnoser/worker 租约 → M2 流式与动态角色 → M3 质量与评测推进，分支 feature/multi-model，详见 PLAN_MULTI_MODEL_RUNTIME。动态角色=注册的 RoleSpec+有界子图提议，编排器确定性，角色只提议；该文件覆盖“不增加任意动态图/并发 Agent”旧约束，其余证据原则不变。main 与 develop 已于 f5fd53d 对齐（main 原只有 LICENSE 的 Initial commit）。

- 2026-10-03 前端 v3（用户授权推翻旧布局约定）：前后端完全分离，前端 TypeScript 独立运行，后端只提供 API；布局为任务历史 + 顶部执行图 + 对话·决策/代码/验证/日志标签 + 右侧 Inspector + 独立设置中心，覆盖此前所有“四标签/状态侧栏/检查图不展示”约定。前端只投影后端事实；服务端状态只放 TanStack Query，组件不写轮询；手动浏览关闭“跟随执行”。后端卡顿根因已记录在 PLAN_FRONTEND_REDESIGN 第 6 节，先搁置。

- 2026-10-03 最新修复约定：用户确认硬件面板，已接入只读缓存采集，无需提权。Planning 假卡死先核对角色账本、待答状态与 HTTP；新本地生成逐文件保存，旧任务保持契约，未知响应不重放。真实失败也完整说明，不宣称通用本地生成已稳定。完整代码说明 USER_LOCAL_RUNTIME_AND_RECOVERY，当前接续进展005。

- 2026-10-03 最新优先级：先纯本地模型可用，优先 glm-4.7-flash；云端和复杂多模型功能暂缓，不自动回退API。前端需要Ollama控制入口、模型列表/大小/切换/详细计数，项目阶段/速率/运行时间常驻顶部。硬件监控可暂缓，不要求管理员权限。

- 2026-10-03 本机已有 Ollama gemma4:12b，开始多模型适配。默认本地L1、API L2，等级由用户指定。唯一实施计划 PLAN_MULTI_MODEL；任务快照与总预算先于自动升级。保留固定模式，不绕过未知请求保护、provider/input 一致性或冻结测试。

- 2026-10-03 用户再次授权大幅重构前端：当前采用项目历史、中央四标签、状态侧栏；新建需求表单仅新项目显示，已有项目底部为状态条。此项覆盖10-02“永久底部需求框”的布局约定。状态须区分需求澄清、审核、模型失败和真实工具失败；手动看历史不得被后台轮询抢回。持续对话仍是愿景，不做不能用的聊天框。

- 2026-10-02 最新方向覆盖旧图布局约定：执行架构减法，中央代码、紧凑顶部进度、底部固定需求框、侧栏历史；不用阶段跳转滚动整个页面。检查依赖图不再展示，底层调度/Gate保留。路由先按现有 Settings/Coordinator/RoleRuntime 扩展，禁止新重复状态体系、任意动态图和多 Agent 并发。具体见 PLAN_MODEL_ROUTING_AND_WORKBENCH。

- 用户要求：先检查并妥善保存已有改动，每完成一个经过验证的独立增量，及时 `git commit`，便于回滚。不要只在会话最后提交；不要提交密钥、运行数据库、临时工作区或不相关改动。
- 函数功能与核心逻辑添加中英文对照注释。优先交付小而可用的纵向流程，避免为个人项目引入过重架构。
- 完成后更新状态、易读进展报告和下一阶段计划，所有项目 Markdown 放在 docs 中。
- 前端是主要使用入口；目标是自然语言生成完整 Go 项目文件夹，经人工审核后通过 harness 执行与验证，结果可观察、可追溯。
- 区分真实 LLM、脚本策略、测试通过与业务正确；不得将路线中的能力描述为已经实现。
- 角色负责决策，检查节点负责具体动作；Runtime 校验计划与工具请求，Gate 独立核对真实结果。不得用 Agent 自称通过代替验收，不把 test/vet/format 当作三个决策 Agent。
- 2026-09-28 用户更新：允许 API 密钥保存到本地 Git 忽略文件，重启自动加载；禁止写入文档、代码、日志或 Git。关键功能优先真实 API 验收，预算仍按已授权范围控制；确定性边界回归保留离线测试，不无意义重复付费调用。

- 2026-09-28 架构约定：采用 domain/application/runtime/agents/intelligence/infrastructure/interfaces；React 采用 app/api/features。优先单一项目工作台，模型选择+描述+开始；角色图展示真实状态，结果与人审在下方。先可用闭环，再统一持久角色图，不引入过重平台。

- 2026-09-28 使用者反馈：图要自动定位当前节点，下面只保留当前阶段的关键结果和代码；需有一次授权后自动生成、运行 Go 检查并有界修复的模式。Tester 是测试方案角色，真实 go_test 只在项目代码发布后执行；Gate 只核对真实工具证据。随机数项目证明测试本身可能有导入循环，需独立测试修订，普通实现修复仍冻结测试。
